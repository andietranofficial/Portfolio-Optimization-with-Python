# Optimo: build spec (demo version)

Optimo is a Microsoft Fabric App, built with Rayfin, that helps analysts and investors split money across a set of stocks. It tests 10,000 random weightings, picks the one that best fits a goal, compares it with equal weight and the S&P 500, and checks whether the choice holds up on data it has not seen.

This spec covers a **quick demo** with a deliberately simple back end. A fuller rebuild (Lakehouse pipeline, more features) comes later and is listed under [Later versions](#12-later-versions).

## 1. Goals and scope

**Who uses it:** analysts and investors at work, on a desktop screen (designed at 1920 × 1080). No mobile layout.

**What the demo must do**

1. Let a signed-in user pick 2–10 stocks from a prepared list.
2. Run 10,000 Monte Carlo weightings and pick a winner for one of two goals:
   - **Best risk-adjusted return**: highest Sharpe ratio.
   - **Best return within a risk limit**: highest expected return with volatility at or below a limit.
3. Compare the result with **equal weight** and the **S&P 500**.
4. Run a **forward test**: choose weights on earlier data, test them on the last 3, 6 or 12 months.
5. Save, reopen and delete scenarios per user.
6. Explain itself: a "How it works" panel and ⓘ tooltips.
7. Show an **AI Assistant** button and panel marked "Coming soon".

**Not in the demo**

- Live Yahoo Finance calls from the app (prices come from a seed file).
- Base currency conversion (everything in USD; see [risks](#11-risks-and-open-questions)).
- Rebalance trades from current holdings, data quality screen, ESG, stress tests, report export.
- Lakehouse pipeline and Power BI reporting.
- Mobile layout.

## 2. Decisions so far

| Topic | Decision |
|---|---|
| App name | **Optimo** |
| Platform | Microsoft Fabric App built with Rayfin (TypeScript data models, React front end) |
| Price source | Yahoo Finance daily **adjusted close**, downloaded once into a seed file |
| Storage | The app's own Fabric SQL database created by Rayfin. No Lakehouse in the demo |
| Optimiser | Monte Carlo, 10,000 scenarios, as in the notebook, plus a per-stock weight cap |
| Goals | Both: highest Sharpe, and highest return under a volatility limit |
| Benchmark | S&P 500, using SPY from Yahoo Finance |
| Forward test | Included, test windows of 3M / 6M / 12M, default 6M |
| Tickers | Max 10 per run. Final list supplied at build time |
| Currency | USD for the demo |
| Screen | Desktop, 1920 × 1080 |
| User | Name from Entra sign-in, e.g. "Andie Tran" |

## 3. Architecture (demo)

```
Yahoo Finance
     │  scripts/download_prices.py  (run once, on a laptop or in a Fabric notebook)
     ▼
seed/prices.csv + seed/tickers.csv   (committed to the repo)
     │  Rayfin seed step (one-time load)
     ▼
Fabric SQL database (created by Rayfin)
  Ticker · PriceBar · Scenario
     ▲  GraphQL API generated by Rayfin
     │
Optimo front end (React + TypeScript)
  ├─ engine/   pure TypeScript maths, runs in the browser (Web Worker)
  └─ ui/       views and components matching the mockup
```

**Why the maths runs in the browser:** 10 stocks × 10,000 scenarios is about 1 million multiply-adds. It finishes in well under a second, needs no server code, and keeps the back end to plain data reads and writes. Run it in a Web Worker so the screen never freezes.

## 4. Data

### 4.1 Seed files

`seed/prices.csv`, long format, one row per stock per trading day:

```csv
symbol,date,adj_close
AAPL,2021-11-22,159.142395
SPY,2021-11-22,447.381012
```

`seed/tickers.csv`:

```csv
symbol,name,currency,is_benchmark
AAPL,Apple Inc.,USD,false
SPY,SPDR S&P 500 ETF Trust,USD,true
```

Produce both with:

```bash
pip install yfinance pandas
python scripts/download_prices.py --tickers <your tickers> --years 2
```

The script always adds SPY, prints row counts per ticker and flags short histories. The demo uses **2 years** of prices, so the look-back buttons are **1Y and 2Y** (hide 3Y and 5Y). If you already have the 2-year download in another format, convert it to these two files. Note that `.gitignore` excludes `data/`, so seed files live in `seed/`.

### 4.2 Data model (Rayfin, TypeScript)

Adapt the decorator syntax to the current Rayfin SDK. Field names and types are the contract.

```ts
// rayfin/data/ticker.ts
@Model()
export class Ticker {
  @Key() symbol!: string;          // "AAPL", "SPY"
  @Field() name!: string;          // "Apple Inc."
  @Field() currency!: string;      // "USD"
  @Field() isBenchmark!: boolean;  // true only for SPY
}

// rayfin/data/priceBar.ts
@Model()
export class PriceBar {
  @Key() symbol!: string;
  @Key() date!: string;            // ISO "YYYY-MM-DD"
  @Field() adjClose!: number;
}

// rayfin/data/scenario.ts
@Model()
export class Scenario {
  @Key() id!: string;              // uuid
  @Field() ownerId!: string;       // Entra object id of the signed-in user
  @Field() name!: string;          // "Big Tech core"
  @Field() settingsJson!: string;  // ScenarioSettings, see 5.1
  @Field() summaryJson!: string;   // ScenarioSummary, see 5.1
  @Field() createdAt!: string;     // ISO timestamp
}
```

Rules:

- Scenarios are per user. Every query and mutation on `Scenario` filters by the signed-in user's `ownerId`.
- `PriceBar` and `Ticker` are read-only for the app. Only the seed step writes them.
- Store results as a **summary** (headline numbers and weights), not the 10,000 scenarios. Reopening a scenario reruns the engine, which is deterministic (see 5.3).
- Change schemas only in `rayfin/data`. Don't edit the SQL database directly.

### 4.3 Data access

| Operation | Purpose |
|---|---|
| `tickers()` | Fill the ticker search box and the benchmark |
| `prices(symbols, from, to)` | Load prices for the chosen stocks + SPY for the look-back window |
| `scenarios()` | "My scenarios" list for the current user |
| `createScenario(input)` / `deleteScenario(id)` | Save and delete |

The look-back window ends at the latest date in the seed data, not at today. The page shows "Prices as of {date}".

## 5. Optimisation engine (`src/engine/`)

The engine is pure TypeScript with no UI or network code, so it can be unit-tested against the notebook.

### 5.1 Types

```ts
export type Goal = 'maxSharpe' | 'maxReturnUnderVol';

export interface ScenarioSettings {
  symbols: string[];        // 2–10, order kept for display
  lookbackYears: 1 | 2;     // demo has 2 years of data
  amount: number;           // USD, default 10_000
  goal: Goal;
  volCap: number;           // e.g. 0.25, used when goal = maxReturnUnderVol
  riskFree: number;         // e.g. 0.04
  maxWeight: number;        // e.g. 0.60, min is ceil(1/n) rounded up to 5%
  forwardTestDays: 63 | 126 | 252;  // 3M / 6M / 12M
}

export interface PortfolioStats { ret: number; vol: number; sharpe: number; }

export interface RunResult {
  weights: number[];            // chosen portfolio
  stats: PortfolioStats;
  equalWeight: PortfolioStats;
  benchmark: PortfolioStats;
  cloud: { ret: Float64Array; vol: Float64Array; sharpe: Float64Array; weights: Float64Array }; // for the frontier chart
  acceptedScenarios: number;    // can be < 10,000 with a tight weight cap
  fallbackToMinVol: boolean;    // true when no scenario meets the volatility limit
  forwardTest: ForwardTestResult;
}

export interface ScenarioSummary {
  weights: Record<string, number>;
  stats: PortfolioStats;
  valueToday: number;
  forwardVerdict: 'heldUp' | 'mostly' | 'didNot';
}
```

### 5.2 Calculations

Use **252 trading days per year** throughout, as the notebook does.

1. **Align dates:** keep only dates where every selected stock and SPY have a price (inner join). Slice to the look-back window.
2. **Daily returns:** `r[t] = p[t] / p[t-1] - 1`.
3. **Annualised mean and covariance:** `mu = mean(r) × 252`, `cov = sampleCov(r) × 252`. Use the sample covariance (divide by N − 1), like pandas `cov()`.
4. **Portfolio stats** for weights `w`:
   - `ret = w · mu`
   - `vol = sqrt(wᵀ · cov · w)`
   - `sharpe = (ret − riskFree) / vol`

   The notebook assumes a risk-free rate of 0; Optimo makes it an input.
5. **Monte Carlo** (same method as the notebook):
   - draw `n` uniform randoms and divide by their sum
   - **reject** the draw if any weight is above `maxWeight`
   - stop at 10,000 accepted draws, or after 600,000 attempts
6. **Pick the winner:**
   - `maxSharpe`: the highest Sharpe.
   - `maxReturnUnderVol`: the highest `ret` among scenarios with `vol ≤ volCap`. If none qualify, return the lowest-volatility scenario and set `fallbackToMinVol = true`.
7. **Equal weight:** `w = 1/n` for every stock.
8. **Benchmark:** apply the same return, volatility and Sharpe formulas to SPY alone.
9. **Growth (buy and hold):** `value[t] = amount × Σ wᵢ × pᵢ[t] / pᵢ[0]`. No rebalancing.
10. **Performance summary**, for Optimo, equal weight and S&P 500:
    - value today, total return and peak value
    - max drawdown: the largest fall from a peak to a later low
    - best day, worst day, and % of days up
11. **Correlation matrix** from the daily returns.

### 5.3 Forward test

1. Split the window: the **training** period is everything except the last `forwardTestDays`; the **test** period is the last `forwardTestDays`.
2. Run steps 3–6 on the training period only, with the same goal and limits, to get `wTrain`.
3. Buy `wTrain` on the first test day and hold it. Do the same for equal weight and SPY.
4. Report for each of the three, over the test period:
   - return
   - Sharpe (from daily returns, annualised)
   - max drawdown
   - volatility
5. **Verdict**, based on Optimo vs equal weight on return, Sharpe and max drawdown:
   - wins 3 of 3: "Held up on unseen data"
   - wins 2: "Mostly held up"
   - wins 0–1: "Did not hold up"
6. **Weight stability:** show `wTrain` next to the full-period weights for each stock.

### 5.4 Randomness

- Use a **seeded random generator** (mulberry32, seed 3, the same seed number as the notebook) so the same inputs always give the same result.
- This lets "Open scenario" reproduce the saved numbers.
- The sequence will not match NumPy's, so tests check properties and tolerances, not exact weights.

### 5.5 Edge cases

| Case | Behaviour |
|---|---|
| Fewer than 2 stocks | Run button disabled, message "Keep at least 2 stocks to optimise." |
| More than 10 stocks | Add blocked, message "You can optimise up to 10 stocks. Remove one first." |
| `maxWeight` below `1/n` | Raise it to the minimum and show it in the field |
| Few draws accepted | Show "{k} scenarios met your per-stock limit" under the frontier |
| No scenario under the volatility limit | Fall back to min volatility, title "No portfolio meets your limit", toast with the reason |
| Stock history shorter than the window | Shorten the window to the common range and show a note |
| Forward test leaves under 60 training days | Disable the longer test windows |

### 5.6 Tests (`src/engine/*.test.ts`)

Test the TypeScript engine against Python results from **your own 2-year seed data**, so both sides use the same prices:

```bash
python scripts/reference_values.py --prices seed/prices.csv --tickers <4 tickers> --risk-free 0
```

The script prints the expected values, using the same formulas as the notebook (pandas/NumPy). Copy them into the test file:

| Check | Tolerance |
|---|---|
| Equal-weight cumulative return (buy and hold) | 1e-4 |
| Equal-weight mean and std of daily return | 1e-6 |
| Equal-weight annualised Sharpe (rf = 0) | 1e-3 |
| Annualised mean return and volatility per stock | 1e-4 |
| Correlation matrix | 1e-3 |
| Equal-weight expected return / volatility (covariance method) | 1e-4 |
| Best Sharpe from 10,000 draws (rf = 0, no cap) | ±0.02 (random sequences differ from NumPy) |

Earlier check of the method: on the notebook's original 2019–2021 data, these formulas gave a best Sharpe of 1.832 at 62.8% return and 34.3% volatility, matching the notebook's own frontier chart.

Property tests:

- Every weight vector sums to 1 (±1e-9) and respects `maxWeight`.
- Same settings give an identical result twice.
- The chosen portfolio's Sharpe is at least the equal-weight Sharpe for `maxSharpe`.
- With `maxReturnUnderVol`, the chosen volatility is at most `volCap` unless `fallbackToMinVol` is set.
- The forward test uses no price after the split date to choose `wTrain`.

### 6.3 Behaviour

- **Stale state:** any input change shows "Inputs changed. Run to update." and the Run button pulses until the next run.
- **Frontier:**
  - hover any dot to see its stats and weights
  - click a dot to open the pick strip, then "Use these weights" to switch every view to that portfolio
  - the optimal portfolio, equal weight and S&P 500 are always marked
- **Compare with:** switches the headline card deltas between equal weight and S&P 500. For volatility, lower counts as better (green).
- **Performance card:** the Summary / Forward test toggle also switches the growth chart between buy-and-hold over the full period and the forward-test view (shaded test zone, "weights fixed {date}").
- **Save scenario:**
  - an inline name field, pre-filled e.g. "AMD / AAPL / MSFT +1 · Sharpe"
  - saving shows the toast "Saved to My scenarios"
  - opening a saved scenario restores its settings and reruns the engine
- **Copy CSV:** copies `ticker,name,weight_optimised,weight_equal,amount_usd,shares`. The demo copies to the clipboard; the full app can download a file.
- **Numbers:** Swiss formatting with an apostrophe as the thousands separator (`USD 10'000`), percentages to 1 decimal, Sharpe to 2. Use tabular figures.

## 11. Risks and open questions

| Item | Impact | Plan |
|---|---|---|
| Rayfin is in preview | APIs and region availability can change | Check the Fabric Apps region for your capacity before M1; keep the engine independent of Rayfin |
| Yahoo Finance has no official API | The download can fail or change | Only used offline in the demo; keep the script simple and re-runnable |
| Non-USD tickers (e.g. Schneider, Vestas, Tomra) | Returns and correlations are distorted without FX conversion | Use USD listings or ADRs for the demo, or add base-currency conversion in v2 |
| Past data drives the result | Users may read weights as a forecast | Forward test, verdict banner, help copy, "not investment advice" badge |
| Monte Carlo is approximate | Best-of-10,000 is close to, but not exactly, the true optimum | Fine for the demo; a proper solver is listed for later |
| Your existing code | May replace parts of this spec (e.g. download script, data access) | Add it to the repo and map it to sections 4–5 before M1 |
